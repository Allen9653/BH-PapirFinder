# Project Summary
BH PapirFinder is a digital public-service and document-preparation platform for residents of Bosnia and Herzegovina. It helps users find institutions, official websites and forms, and prepare documents through its generator. The directory combines Supabase records with built-in data so core information and forms can remain available when the database is unavailable.

The platform includes a responsive business footer and FAQ, Impressum, cookie, privacy, terms, and legal-source pages. Interface text is available in five languages. The FAQ’s structured data is generated from the same question data shown to visitors.

Temporary document copies stored in the browser are automatically removed after five hours. PDF share links expire after five hours. Server-side deletion is prepared but is not active until the Supabase setup in `supabase/auto-delete-5h.sql` is completed and the frontend setting is enabled. The app does not currently generate JS3000, MIP-1023, or GPD-1051 forms; users are directed to official sources and advised to check current forms before submitting.

Official institution website buttons use only `public.institucije.official_url`. A button is hidden when the value is empty or is not a valid HTTPS URL; valid links open in a new tab with security attributes. Static data and other database fields are not fallback sources for these buttons.

Account deletion is not automated: signing out clears browser-stored data, while permanent account and Supabase data deletion must be requested by contacting support. Duplicate-cleanup and website-link SQL scripts remain unapplied. Type checks, lint, and production build pass. Republish to publish frontend changes.

## Project Module Description
- **Institution directory and search:** Combines database and built-in records. Website buttons require a valid HTTPS `official_url`; repeated institution results are filtered where possible.
- **Institution and municipality pages:** Search results, autocomplete, institution pages, and municipality forms share the official-link rule.
- **Document template generator:** `/generator` provides template cards, language selection, form fields, previews, and document actions. Templates require a Supabase read grant.
- **Document retention:** Browser-stored generated and saved documents are checked on app load and every five minutes, and copies older than five hours are removed. PDF share links expire after five hours. Scheduled deletion of server database rows and storage files is prepared but inactive until Supabase configuration is completed.
- **Accounts and dashboard:** Account, subscription, document, and dashboard features.
- **Footer and site navigation:** Responsive business footer with company details, navigation, legal links, support contacts, and copyright information.
- **FAQ:** `/faq` presents nine questions. FAQPage JSON-LD is derived from the visible FAQ data. Answers avoid unsupported guarantees about tax authority acceptance or server-side deletion.
- **Company and legal information:** `/impressum`, `/privacy`, `/terms`, and `/cookies` describe the organization, data handling and retention, service limitations, and analytics consent.
- **Legal sources:** `/zakoni` links to official legal sources rather than reproducing or inventing laws.
- **Localization:** Interface and new page text are available in five languages.

## File Description Inventory
- `src/lib/doc-retention.ts`: Removes browser-stored document copies older than five hours on app load and every five minutes. Server purge remains disabled until configured and activated.
- `src/lib/pdf-storage.ts`: Handles PDF storage and five-hour share-link expiry.
- `supabase/auto-delete-5h.sql`: Prepared scheduled deletion for old `user_document_logs` rows and files in the generated-document storage folder. It has not been activated; requires `pg_net`, a stored service-role key, and enabling the frontend server-purge setting.
- `src/pages/FAQ.tsx`: Displays nine FAQ questions and creates FAQPage JSON-LD from the same question data.
- `src/pages/Privacy.tsx`: Explains browser processing and the current five-hour retention behavior without claiming that server-side deletion is active.
- `src/pages/Terms.tsx`: States the platform’s independent status, user responsibilities, service limitations, and lack of guarantees about authority acceptance.
- `src/pages/Impressum.tsx`: Presents company information, including the full company name.
- `src/locales/`: Includes translations for the new and revised content in five languages.
- `src/lib/institution-directory.ts`: Shared institution matching and official website URL handling; website buttons use only `institucije.official_url`.
- `src/pages/SearchResults.tsx`, `src/pages/InstitutionPage.tsx`, and `src/pages/MunicipalityForms.tsx`: Show website buttons only for valid HTTPS `official_url` values.
- `supabase/dedupe-institucije.sql`: Prepared duplicate-cleanup transaction; review before execution. It has not been run.
- `.atoms/PROGRESS.md`: Records project progress.

## Usage
From the application directory:

1. Install dependencies:
   ```bash
   pnpm install
   ```
2. Start the development app:
   ```bash
   pnpm run dev
   ```
3. Build for production:
   ```bash
   pnpm run build
   ```
4. Run lint checks:
   ```bash
   pnpm run lint
   ```

Configure the Supabase project URL and public anon/publishable key using the expected `VITE_` environment variables. Do not place service-role credentials or database passwords in frontend code.

To enable generator templates, run in the Supabase SQL Editor:
```sql
GRANT SELECT ON public.text_document_templates TO anon, authenticated;
```

Server-side five-hour deletion is not active by default. To enable it, turn on `pg_net` in Supabase, store the service-role key securely in Vault as described in `supabase/auto-delete-5h.sql`, and run that SQL script. Then set `SERVER_PURGE_ACTIVE = true` in `src/lib/doc-retention.ts` and republish. Review the retention script and verify its configuration before activation.

Review `supabase/dedupe-institucije.sql` before running it. The duplicate-cleanup and institution-link update scripts are unapplied. Republish the app to publish frontend changes.
